Contributing
===========

Thanks for helping improve this project! Keep changes small, focused, and well-tested.

Getting started
- Fork the repo and create a branch: git checkout -b feat/short-description
- Install dependencies (see README). Common commands: npm install, pip install -r requirements.txt, go mod download
- Run tests and linters before committing (e.g. npm test, pytest, go test)

How to contribute
- Open an issue if one does not exist before implementing large changes
- For bug fixes or features: include tests and update docs where applicable
- Make commits atomic and use clear messages in imperative mood (e.g. "fix: handle nil input")

Pull request checklist
- Tests pass locally and in CI
- New code is covered by tests where reasonable
- Documentation updated if behavior or API changed
- Small, focused PR with a clear description and linked issue (if any)

Reporting bugs
Provide steps to reproduce, expected vs actual behavior, environment (OS/runtime versions), and a minimal reproduction if possible.

Code review
Be responsive and respectful to review feedback; explain design decisions when requested.

Communication
Follow the project's Code of Conduct. If you need private help or need to report a sensitive issue, open a private issue or contact the maintainers.

Thank you for contributing!
